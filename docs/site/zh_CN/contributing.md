# 参与贡献

## 哪些改动最适合放在这个仓库里

通常比较合适的贡献包括：

- Arduino Core 功能实现或修复
- variant / target 改进
- 示例新增和修复
- staging、打包、导出工具链改进
- 缩短用户从 checkout 到成功验证路径的文档优化

## 先说清楚你改的是哪一层

提交改动时，最好明确它属于哪一层：

- Arduino-facing 源码和 API
- variant 映射和板级假设
- 平台 staging / 打包流程
- 导出 SDK 行为
- 面向用户的文档

这样 review 会容易很多。

## 优先做能被示例支撑的改动

如果改动会影响用户可见行为，尽量同步补一个示例或更新现有示例。这个仓库本来就把 examples 同时当作说明材料和验证锚点。

## 尽量让改动小而可验证

更容易 review 的改动通常满足：

- 只解决一个问题
- 不夹带无关清理
- 清楚说明影响哪个 target
- 明确写出跑了哪条验证路径

## 验证预期

至少应说明做了哪些验证：

- `prepare-platform`
- `cli-compile`
- 直接 `bk_idk` build
- 如果相关，真实硬件验证

## 文档改动同样有价值

只要它能减少 bring-up、打包或 target 假设上的歧义，文档优化也是这个仓库里很有价值的贡献。
