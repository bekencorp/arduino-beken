# arduino-beken Scripts

Language: English | [简体中文](tools_CN.md)

This document describes the scripts under `tools/` and focuses on:

1. What each script does
2. Who normally invokes it

This document does not cover the binary uploader payloads under `tools/bk_loader/` (`linux/`, `windows/`, optional `macos/arm64/`, `macos/x86_64/`) or data files such as `tools/toolchains.json`.

## How To Read This

These scripts can be grouped into four areas:

1. Platform staging and core wrapper generation
2. `bk_idk` direct-build helpers
3. Arduino CLI / IDE build and upload flow
4. SDK export and release packaging

In most cases, the real entrypoint is not the script itself but `Makefile` or `platform.txt`.

## Terms

### Staging

In this repository, `staging` means copying and rewriting repository content into a generated Arduino-platform tree under `build/`, so Arduino CLI / IDE can consume it as a self-contained hardware package.

Typical staged outputs include:

- `build/platform/<target>/arduino-beken/`
- `build/platform-cli/<target>/arduino-beken/`

### Core wrappers

Arduino CLI and the platform layout expect standard core file names under `cores/arduino/` (`Arduino.cpp`, `HardwareSerial.h`, and so on). The real implementations for this port live under `components/arduino-beken-core/` and `components/arduino-beken-main/` for `bk_idk` / CMake.

**Core wrappers** are auto-generated thin files (usually a single `#include` into `components/...`) that:

- Expose the Arduino directory layout without copying logic twice
- Keep a single source of truth in `components/`
- Are regenerated whenever the platform is staged (`prepare-platform`)

### Sketch pipeline wrappers

Separately from core wrappers, a few scripts emit small glue sources for sketches:

- the sketch wrapper generated by `bk_prepare_core.py`
- the extra translation units generated by `sketch_prep.py` for sibling sketch sources

## 1. Platform staging and core wrapper generation

### `tools/stage_platform.py`

Role:

- Direct entrypoint for `prepare-platform`
- Generates `build/platform/<target>/arduino-beken/`
- Generates `build/platform-cli/<target>/arduino-beken/`
- Updates the local `.arduino-cli-test/user/hardware/beken/<target>` symlink

Invoked by:

- [Makefile](../Makefile)

### `tools/platform_tree.py`

Role:

- Low-level implementation behind `stage_platform.py`
- Copies `components/`, `variants/`, `libraries/`, `examples/`, and `tools/`
- Generates staged `boards.txt`
- Rewrites staged `platform.txt`
- Generates the staged `cores/arduino/` core wrappers

Invoked by:

- [tools/stage_platform.py](../tools/stage_platform.py)
- [tools/make_release.py](../tools/make_release.py)

### `tools/gen_boards_txt.py`

Role:

- Scans `config/<target>` and `variants/` for a selected `TARGET`
- Computes flash size, app partition size, default upload speeds, and partition-scheme board properties
- Generates staged `boards.txt`
- Emits `menu.PartitionScheme` automatically when multiple `auto_partitions*.csv` files exist

Invoked by:

- [tools/platform_tree.py](../tools/platform_tree.py)

### `tools/ide/bk_generate_partitions.py`

Role:

- Invoked by the `platform.txt` prebuild hook before normal compilation
- Selects the active partition CSV from `build.partitions_csv`
- Creates a synthetic project root for the current Arduino build
- Calls the exported upstream partition generator from the SDK
- Produces build-local `partitions_gen.h`, `partitions.h`, `bk_package.json`, and `bk_ota_partitions.json`

Invoked by:

- [platform.txt](../platform.txt)

### `tools/core_wrappers.py`

Role:

- Defines the staged `cores/arduino/` core-wrapper mapping (`CORE_SOURCE_MAP`, `CORE_HEADER_MAP`)
- Points each wrapper at `components/arduino-beken-core/` or `components/arduino-beken-main/`
- Defines which wrapper files are omitted from the staged platform (`STAGED_CORE_PRUNED_FILES`)

Invoked by:

- [tools/platform_tree.py](../tools/platform_tree.py)
- [tools/generate_core_wrappers.py](../tools/generate_core_wrappers.py)
- [tools/check_core_wrappers.py](../tools/check_core_wrappers.py)

### `tools/generate_core_wrappers.py`

Role:

- Writes thin `#include`-only core wrapper files into a chosen `cores/arduino/` directory from `tools/core_wrappers.py`
- The [Makefile](../Makefile) target `sync-core-wrappers` writes into the **repository root** `cores/arduino/` (full manifest, including files that staged builds omit such as `GeneratedSketch.cpp` / `main.c` / `init_stub.c`)
- Useful after editing `CORE_SOURCE_MAP` / `CORE_HEADER_MAP` so local tooling or editors that still open repo-root `cores/arduino/` stay in sync; release and `arduino-cli` flows consume the **staged** tree from `prepare-platform` instead

Invoked by:

- [Makefile](../Makefile) via `sync-core-wrappers`

### `tools/check_core_wrappers.py`

Role:

- Verifies that staged `cores/arduino/` is complete
- Verifies that each wrapper matches the `core_wrappers.py` manifest
- Regenerates into a scratch directory and checks the generated file set matches expectations
- Can be used as a CI or regression check

Invoked by:

- [Makefile](../Makefile) via `check-core-wrappers` (this target depends on `prepare-platform`, so a fresh staged platform is always validated)

## 2. `bk_idk` Direct-Build Helpers

### `tools/sketch_prep.py`

Role:

- Serves `make build`
- Normalizes an Arduino sketch directory into compilation units that `bk_idk` can consume directly
- Merges the primary `.ino` and sibling `.ino` files
- Generates extra wrappers for sibling `.c` / `.cpp` files

Invoked by:

- [Makefile](../Makefile)

### `tools/patch_linker_script.py`

Role:

- Patches a linker script generated by `bk_idk`
- Restores `.preinit_array` / `.init_array` / `.fini_array`
- Ensures C++ global constructor and destructor tables remain available

Invoked by:

- [components/arduino-beken-linker/CMakeLists.txt](../components/arduino-beken-linker/CMakeLists.txt)

## 3. Arduino CLI / IDE Build And Upload Flow

### `tools/ide/bk_prepare_core.py`

Role:

- Invoked by the `platform.txt` prebuild hook
- Generates `GeneratedSketch_<hash>.cpp` inside the current build's `core/` directory
- Keeps `setup()/loop()` inside `core.a`
- Forces the core archive to change when the sketch path changes, so IDE builds do not reuse an old sketch payload

Invoked by:

- [platform.txt](../platform.txt)

### `tools/ide/bk_compile.py`

Role:

- Lightweight wrapper around the Arduino platform compile recipes
- Reads exported SDK flag files
- Expands and runs the real compiler command

Invoked by:

- [platform.txt](../platform.txt)

### `tools/ide/bk_builder.py`

Role:

- Implements Arduino platform link / objcopy / final image packaging
- Links the ELF
- Produces the `.bin`
- Produces sketch-specific `*.all-app.bin`
- Keeps the compatibility copy `all-app.bin`
- Prefers build-local partition JSON over the static SDK copy
- Filters standalone `sketch/*.ino.cpp.o` objects to preserve the current validated link semantics

Invoked by:

- [platform.txt](../platform.txt)

### `tools/ide/bk_uploader.py`

Role:

- Wrapper for the Arduino platform upload recipe
- Converts port, baud, and input-image parameters into `bk_loader download`
- Always passes `--reboot`

Invoked by:

- [platform.txt](../platform.txt)

## 4. SDK Export And Release Packaging

### `tools/export_sdk.py`

Role:

- Extracts an Arduino-reusable SDK from a baseline `bk_idk` build
- Exports includes, flags, libs, linker scripts, bootloader, partitions, and package materials
- Exports the minimal partition-generation runtime needed by Arduino CLI / IDE
- Produces `dist/sdk/<target>/manifest.json`

Invoked by:

- [Makefile](../Makefile)

### `tools/make_release.py`

Role:

- Generates release artifacts from the staged platform and exported SDK
- Produces platform archives, SDK archives; toolchain references are handled via URLs in package index
- Produces `package_beken_<target>_index.json`
- Also implements the lightweight `release-check` archive flow

Invoked by:

- [Makefile](../Makefile)
